# 新手宠物养护助手 MVP 需求规格

> 规格编号：PET-MVP-001  
> 状态：基线已确认  
> 来源：[project-doc.md](../../../project-doc.md)  
> 适用版本：MVP

## 1. 背景与问题

第一次养宠物的用户通常同时面临两个问题：养之前不知道什么宠物适合自己的生活条件，养之后又不知道当前阶段应该做什么。现有百科式内容要求用户先理解大量知识，再自行判断哪些内容适用于自己的宠物。

本产品把信息转化为决策和行动：在养宠前帮助用户比较选择，在养宠后根据宠物档案生成当前任务、近期提醒和阶段重点。

## 2. 用户角色

### P1 尚未决定的新手

正在考虑养宠物，不清楚猫、狗或其他宠物的时间、预算、空间和长期责任差异。

### P2 已决定但尚未接宠的新手

已经决定宠物类型或品种，需要用品准备、环境布置和到家第一周指导。

### P3 已经拥有宠物的新手

需要喂养、疫苗、驱虫、训练、清洁和健康观察的每日计划。

### P4 回访用户

已经建立档案，希望完成今日任务、查看近期提醒并了解当前成长阶段。

## 3. 用户旅程

### J1 从选择开始

首页 → 适宠测评 → 推荐结果 → 宠物对比 → 宠物详情 → 接宠前准备。

### J2 从明确目标开始

首页 → 选择宠物类型 → 新手路线图 → 创建档案 → 今日计划。

### J3 从已有宠物开始

首页 → 创建宠物档案 → 补充健康记录 → 今日计划 → 完成任务。

### J4 日常回访

打开网站 → 今日计划 → 勾选任务 → 查看近期提醒 → 查看阶段建议或异常提示。

## 4. 功能需求

### 4.1 首页与宠物选择

#### FR-001 首页提供双入口 P0

首页必须同时提供“帮我选择适合的宠物”和“我已经知道养什么”两个清晰入口。

**验收标准**

- 用户无需注册即可进入任一流程。
- 首屏说明网站可以帮助选宠和制定养护计划。
- 两个入口在 360px 宽度下无需横向滚动。

#### FR-002 展示五类宠物入口 P0

系统必须展示狗、猫、鱼、乌龟和鹦鹉五类宠物，并提供寿命、预算、空间、时间投入和主要难点的摘要。

**验收标准**

- 每个宠物入口都可访问。
- 内容深度不足的宠物必须标注当前可用范围，不伪装成完整计划。

### 4.2 适宠测评与比较

#### FR-003 完成适宠测评 P0

系统必须根据居住空间、每日时间、预算、出差频率、噪声接受度、掉毛接受度、家庭成员和互动期待生成匹配结果。

**验收标准**

- 用户可以返回修改答案，已填写内容不丢失。
- 可跳过非关键问题；系统必须说明因此采用的默认假设。
- 提交前显示答题进度。

#### FR-004 解释测评结果 P0

测评结果必须给出多个候选及其适合度、推荐理由、主要代价和需要重新考虑的条件。

**验收标准**

- 不使用“唯一适合”或保证性表达。
- 至少显示一个推荐理由和一个注意事项。
- 用户可以查看结果所使用的关键答案。

#### FR-005 支持猫狗比较 P0

系统必须允许用户按时间投入、空间、预算、互动方式、训练需求和日常清洁比较猫与狗。

#### FR-006 支持犬种筛选 P1

系统应该按体型、运动量、掉毛、叫声、训练难度和居住空间筛选犬种，并展示不匹配原因。

**MVP 边界**

- 首版使用有限的演示犬种数据。
- 结果用于初步筛选，不替代对具体犬只性格、健康和来源的考察。

### 4.3 新手路线图

#### FR-007 展示阶段路线 P0

狗和猫必须具有“接宠前、到家第一周、幼年期、成长期、成年期、老年期”路线；每个阶段显示最重要的行动和风险。

#### FR-008 使用六类内容模块 P0

每个完整阶段必须按“吃什么、怎么住、健康、行为或训练、日常护理、为什么”组织内容。

**验收标准**

- 默认先显示可执行摘要，而不是长文章。
- 用户可以展开“为什么”查看解释。
- 内容不存在时显示明确空状态。

#### FR-009 提供接宠前用品清单 P0

系统必须按宠物类型提供用品 Checklist，区分必需、建议和暂不需要。

### 4.4 宠物档案

#### FR-010 无登录创建档案 P0

用户必须可以在不注册的情况下创建宠物档案。

#### FR-011 收集通用档案信息 P0

档案必须支持名称、宠物类型、品种或品系、出生日期或估算年龄、性别、体重、到家日期和备注。

**验收标准**

- 出生日期未知时可以选择年龄区间。
- 关键数据缺失时仍可生成基础计划，但必须显示所用假设。
- 用户可以随时编辑档案并重新生成计划。

#### FR-012 收集专属饲养信息 P1

系统的数据模型必须支持不同宠物的专属字段：

- 狗：体型、运动水平、疫苗、驱虫和绝育状态。
- 猫：室内或室外、猫砂盆数量、疫苗、驱虫和绝育状态。
- 鱼：鱼种、数量、鱼缸容量、过滤、水温和开缸日期。
- 乌龟：品种、水陆环境、晒台、UVB、水温和冬眠计划。
- 鹦鹉：品种、笼舍、每日互动、放飞环境和饮食结构。

MVP 界面只要求完整实现狗和猫，但领域模型不得阻止后三类扩展。

### 4.5 今日计划与记录

#### FR-013 生成个性化今日计划 P0

系统必须根据宠物类型、年龄阶段、健康记录、饲养环境和当前日期生成今日任务。

**验收标准**

- 每项任务显示名称、类别、建议时间或频率、完成状态和简短说明。
- 相同输入在同一天生成稳定结果。
- 规则不适用时不得生成对应任务。

#### FR-014 记录任务完成状态 P0

用户必须能够勾选和取消今日任务，并看到已完成数量和进度。

#### FR-015 展示近期提醒 P0

系统必须根据已有记录展示疫苗、驱虫和护理等即将到来的事项，并区分已过期、即将到期和未来事项。

#### FR-016 展示阶段重点 P0

Dashboard 必须显示宠物当前阶段最值得关注的 1 至 3 项内容，并可进入对应路线图。

#### FR-017 提供建议依据 P0

用户必须可以从任务或提醒打开“为什么”，查看适用条件、解释和内容来源字段。

### 4.6 健康安全

#### FR-018 支持健康异常快速查询 P0

系统必须支持按常见症状查看一般观察建议，并把结果分为：日常观察、建议尽快咨询专业兽医、建议立即就医。

**验收标准**

- 页面持续显示“不能替代兽医诊断”的说明。
- 紧急风险优先显示，不被折叠或弱化。
- 不提供处方药、药物剂量或确诊结论。
- 无法判断时引导用户联系专业兽医。

#### FR-019 记录健康事项 P0

狗猫档案必须支持新增、编辑和删除疫苗、体内驱虫、体外驱虫、体检和绝育记录。

### 4.7 数据与恢复

#### FR-020 本地保存数据 P0

系统必须在浏览器本地保存测评进度、宠物档案、健康记录和任务完成状态。

**验收标准**

- 刷新页面后数据保持。
- 数据结构包含版本号。
- 数据损坏时回退为空状态并提示用户，不使页面崩溃。
- 清除数据前必须再次确认并说明不可恢复。

#### FR-021 支持空状态与首次引导 P0

没有宠物档案时，Dashboard 必须引导用户创建档案或先进行适宠测评，不得显示无解释的空白页面。

## 5. 业务规则

### BR-001 年龄阶段

年龄阶段由宠物类型和年龄共同决定，不使用一个适用于所有宠物的统一阈值。生日未知时使用年龄区间，并在建议中标明精度较低。

### BR-002 测评结果

测评采用多维适合度，不输出绝对结论。硬性冲突条件优先于偏好得分，例如房屋明确禁止宠物时必须先提示现实限制。

### BR-003 规则优先级

健康安全限制高于日常建议。例如疫苗状态不满足外出条件时，限制提示必须覆盖常规遛狗或社交任务。

### BR-004 提醒日期

提醒由明确日期或“上次执行日期加规则间隔”生成。缺少必要信息时显示“待补充”，不得虚构日期。

### BR-005 内容来源

健康和安全类内容必须具备内部来源字段、审核状态和更新时间。未完成审核的内容不得进入生产规则集。

### BR-006 任务幂等

同一宠物、同一日期和同一规则只能生成一个逻辑任务。重新加载或重新计算不得制造重复任务。

## 6. 非功能需求

#### NFR-001 响应式设计

支持最小 360px 宽度以及常见平板、桌面布局；所有主要操作无需横向滚动。

#### NFR-002 无障碍

核心流程达到 WCAG 2.2 AA 的基础要求：语义化结构、键盘可操作、可见焦点、表单标签、错误提示和足够色彩对比度。

#### NFR-003 性能

生产构建中，首页和 Dashboard 的 Lighthouse Performance、Accessibility、Best Practices、SEO 目标均不低于 90；测量环境差异必须记录。

#### NFR-004 隐私

MVP 不收集账号身份信息，不向第三方发送宠物档案。界面必须说明数据保存在当前浏览器。

#### NFR-005 可测试性

业务规则必须以纯函数或可隔离服务实现，页面组件不得直接包含复杂日期和健康判断。

#### NFR-006 可维护性

新增宠物类型、成长阶段、测评维度或养护规则时，应主要通过新增类型化数据和规则完成，而不是复制整套页面。

#### NFR-007 浏览器支持

支持最新两个主要版本的 Chrome、Edge、Safari 和 Firefox。

## 8. 关键验收场景

### AC-001 未决定养什么

```gherkin
Given 用户第一次进入网站且尚未决定养什么
When 用户选择“帮我选择”并完成必填问题
Then 系统展示多个候选宠物的适合度、推荐理由和注意事项
And 用户可以返回修改答案后重新计算结果
```

### AC-002 已决定养狗

```gherkin
Given 用户已经决定养狗但尚未接狗
When 用户从首页选择狗并打开“接宠前”阶段
Then 系统展示环境准备、必需用品和第一周注意事项
And 用户无需先创建账号
```

### AC-003 创建幼犬档案

```gherkin
Given 用户有一只三个月大的幼犬
When 用户填写基本档案、疫苗和驱虫情况并完成创建
Then 系统生成当天的喂养、饮水、清洁或训练任务
And 展示当前阶段重点及适用的健康提醒
```

### AC-004 安全规则覆盖日常任务

```gherkin
Given 幼犬的基础免疫状态不满足犬只密集场所活动条件
When 系统生成当天计划
Then 系统不得建议前往狗公园
And 必须展示限制原因和咨询专业兽医的提示
```

### AC-005 持久化任务状态

```gherkin
Given 用户已经完成一项今日任务
When 用户刷新页面或稍后重新打开网站
Then 今日任务保持完成状态
And 总进度与任务状态一致
```

### AC-006 紧急健康提示

```gherkin
Given 用户选择了被规则标记为紧急的症状组合
When 系统显示查询结果
Then 页面优先显示立即就医建议
And 不给出确诊或自行用药剂量
```

### AC-007 数据损坏恢复

```gherkin
Given 浏览器中的本地数据无法通过版本校验
When 用户打开应用
Then 应用不崩溃
And 提示本地数据无法读取并提供安全重置入口
```

## 9. MVP 发布判定

只有在以下条件全部满足时，MVP 才可标记完成：

- 所有 P0 需求已实现，或有经过记录的范围变更。
- AC-001 至 AC-007 均有自动化或明确的人工验收记录。
- 狗猫内容通过产品审核，健康安全内容通过单独复核。
- 没有阻塞核心流程的严重缺陷。
- 移动端、键盘操作、本地数据恢复和生产构建通过检查。
